## Why this is material

This release changes hardware coverage, request-memory safety and model-family correctness in the embedding/reranking serving layer. The material boundaries are ARM64 and multi-arch CUDA, `sm_121` / DGX Spark, initial AMD ROCm support, bounded `PaddedBatch.from_pb` allocation, NomicBert maximum-position handling, DeBERTaV2 large-batch behavior, and GKE CUDA entrypoint handling. These can change whether an embedding service starts, accepts a request safely, and returns equivalent results.

The estate already contains TEI references, but they are not a production qualification for this source. `platform/replit-sync/FOUNDER_GPU_RUNBOOK.md` still names a `1.5` image, and `holographic-unify/src/lib/sota.ts` categorizes TEI as an embedding-serve job. Those are discovery/deduplication evidence only; do not rewrite them merely because this candidate exists.

## Deterministic retrieval fixtures

Use fixed UTF-8 request inputs and stable, predeclared comparison rules. Minimum coverage:

1. single short sentence embedding;
2. empty/whitespace boundary according to the API contract;
3. Unicode and mixed-script text;
4. long input immediately below the admitted model limit;
5. over-limit input with explicit failure/truncation semantics;
6. deterministic batch ordering across repeated requests;
7. rerank fixture with tied/near-tied documents and stable ordering rules;
8. cancellation/timeout fixture proving no partial result is classified as success;
9. malformed request fixture with explicit non-2xx failure;
10. repeatability fixture across service restart using the exact same bound artifact.

Record dimensions, normalization behavior, rank order, canonical score serialization or output hashes, response status, and PASS/FAIL/UNAVAILABLE. Performance is not a substitute for equivalence.

## Safety and correctness successors

### Bounded PaddedBatch allocation

Construct a bounded adversarial request based on the upstream `PaddedBatch.from_pb` defect class. Prove the exact candidate rejects or bounds the request without uncontrolled allocation, crash-restart loops, silent partial success, or receipt loss. Capture memory telemetry as evidence; do not intentionally exhaust the host.

### NomicBert

Exercise a model/revision whose configuration requires the corrected `max_position_embeddings` behavior. Test boundary lengths around the configured maximum and require explicit, reproducible handling.

### DeBERTaV2

Exercise a representative admitted DeBERTaV2 revision at a small deterministic batch and a larger batch that covers the upstream regression class. Output equivalence and request completion are required before any throughput measurement.
